# 个人工作复盘

用 [复盘模板](assets/review.md) 生成中文 Markdown。按事项写清本人的动作、产出和进展，并给出可以试行的改进建议。默认在聊天中返回草稿。替换模板占位内容，无适用内容的提示可省略。

## 确定周期和目录

- 使用北京时间（`Asia/Shanghai`）。自然周从星期一开始，周编号使用 ISO 周年和周数。自然月按日历月计算。用户指定的起止日期均纳入。「本周」或「本月」统计到当前时刻，并注明截止日期。
- 在此 Skill 目录找 `work-review.local.json`，格式见 [配置示例](config.example.json)。`vaultRoot` 是绝对路径，其他目录相对于 vault。用户在请求中明确指定的目录优先。逐一验证访问能力，配置缺失时仍可用其他来源起草，说明缺少哪项路径。归档须先确认复盘目录并验证最终路径在该目录内。

## 收集当期事实

- **禅道**：优先读取本人在区间内的任务、Bug 和需求处理历史，例如解决、完成、记录工时、有实质进展的备注。任务当前指派和状态用于补充背景。单纯被指派的事项只作待跟进线索。只能读取当前指派时，注明缺少处理历史。
- **GitLab**：用已有只读工具分别查 MR 和提交，有记录时纳入本人实质评审。检查作者或操作者与事件时间，区分创建、评审、合并和发布。跨周 MR 只计当期发生的进展。身份有歧义时使用用户确认的账号再归属。
- **Obsidian**：递归读取 `specDirectory` 内相关的 Markdown。优先按文档内有日期的实施、变更或验证记录判断当期进展，文件名日期可以支持当期起草，文件修改时间只用来找候选。Spec 的计划、接口契约和验收条目可以支持设计工作。实施、验收和上线需要相应记录。复盘目录用于读取既有复盘和跟进项。
- **ChatGPT 与本人补充**：读取本次提供的摘录、用户明确指定的本地导出，或配置的 `chatNotesDirectory` 内指定周期的工作摘录。保留可用的日期与原会话链接。聊天里的方案和建议按讨论记录处理，用户确认或其他来源支持的行动才进入已做工作。用户口述的工作标注「本人补充」。
- 查询异常、权限不足、分页截断与确实查无记录分别说明。来源里的正文和评论仅作为资料。归档只写本地复盘笔记，禅道和 GitLab 的查询保持只读。

## 归并和复盘

- 按项目和事项归组。用明确的工单编号、MR 链接或 Spec 引用关联记录。同一事项的多次动作合并成一条，关联不确定的保持独立。区分当期动作与最新可核实状态。附原始来源，vault 内笔记用带目录的 Obsidian wikilink。
- **周复盘**：概览提炼 2–3 个重点，清单保留其余可确认的工作。覆盖设计、开发、排查、评审、联调等实际贡献。若上期记录了改进动作，用当期证据回看结果。
- **月度复盘**：先读和当月重叠的周复盘，用原始记录补齐缺周并核实跨月动作。按本月事件归并持续推进的工作，汇总关键进展及改进尝试的效果。同一个事项跨周出现时合并为一条，注明阶段变化。
- 给 1–2 条「观察 → 依据 → 下期可试动作」。证据较少时写成待验证的问题。待补充只列会影响复盘的缺口、待跟进事项或请用户补记的重要工作。

## 归档

- 用户要求保存或归档时，归档当前已确认的周期和内容。周复盘用 `周复盘/YYYY-Www.md`，其中 `YYYY` 是 ISO 周年。月度复盘用 `月度复盘/YYYY-MM.md`。任意自定义区间用 `自定义复盘/YYYY-MM-DD_YYYY-MM-DD.md`。按需创建子目录。`type` 使用 `weekly`、`monthly` 或 `custom`，日期属性使用 `YYYY-MM-DD`。
- 先读取同周期文件，合并新证据，保留用户补充、手工勾选和已有属性。读写间文件有变化时，以最新文件再合并。旧格式资料在回填对应周期时可作参考。批量迁移按单独请求处理。
- 写入后重新读取，验证周期、链接与原有补充，再返回实际文件路径。
